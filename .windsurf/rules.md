# Правила и ограничения

## Безопасность

- **Ключи только в ENV Railway** — никогда не коммитить UUID, WS_PATH в код или Git
- **UUID — это пароль** — кто знает UUID + домен + WS_PATH, тот имеет полный доступ к VPN
- **TLS терминируется на Railway** — между Railway proxy и контейнером трафик идёт по внутренней сети (HTTP), это нормально и безопасно
- **Routing правило `geoip:private`** — блокирует доступ к приватным IP-адресам через VPN (защита от сканирования внутренней сети Railway)

## Railway

- **Домен `*.up.railway.app`** — можно задать имя вручную через дашборд (удалить автогенерированный, создать новый с желаемым именем). Для полностью своего домена нужен собственный домен + DNS
- **Деплой только через `git push`** — `railway up` не использовать, чтобы состояние репо и контейнера не расходились
- **ENV-изменения** — при смене переменных Railway автоматически редеплоит контейнер
- **connection.json** — единый источник истины для ссылки подключения. `qr.html` и `rotate-key.sh` читают/пишут его. Не хардкодить ссылку в других местах

## Xray-core

- **WebSocket deprecated** — Xray v24.12.31 предупреждает о миграции WS на XHTTP H2/H3. Пока работает стабильно, но в будущих версиях может быть удалён
- **Версия фиксирована** — `ARG XRAY_VERSION=v24.12.31` в Dockerfile. Обновлять вручную
- **envsubst** — `entrypoint.sh` генерирует `config.json` из `config.json.template`, подставляя `${PORT}`, `${XRAY_UUID}`, `${WS_PATH}` из ENV. Файл `config.json` существует только внутри контейнера в рантайме
- **Один inbound** — при добавлении новых inbound'ов не забывать обновлять `entrypoint.sh` (export переменных) и routing rules

## Ограничения платформы

- **WSL-окружение** — команды выполняются в WSL Ubuntu-22.04, IDE на Windows
- **Нет sudo** — установка системных пакетов через apt невозможна без пароля
- **Нет jq** — не установлен в WSL, GraphQL-запросы через railway-api.sh не работают. Нужно `sudo apt install jq`
- **Node.js v12** — слишком старый для `npm i -g @railway/cli` (нужен 16+)
